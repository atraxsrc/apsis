### Part 1: 0.4.2 "reads that share, one bulk-delete job", branch `release-0.4.2` from `main`

Built exactly as PLAN "0.4.2" on restore-6b-core designs it. Two commits:

- **6361746** `helper, core, applet: reads share, writes wait, one bulk-delete job`
- **3aea553** `release: 0.4.2`

What's in it:

- **Helper `State`**: `read()` admits a reader (a count; no job, no `JobChanged`, never in
  `Job()`); `begin(kind)` is async: it takes the write lock at once (new readers are refused
  `Busy` from then on: writer priority) and waits for the readers in, up to 15 s
  (`WRITE_WAIT`), then gives up `Busy` with the lock freed. `Running::end(state)` takes the
  job out, **frees the lock, then announces**; `State::end` is gone. `State::step` for a
  delete-many's per-snapshot progress (always announced).
- **Shared mount** (`native::SharedMount`): refcounted, keyed by the device UUID; the first
  reader mounts `ro`, the last out unmounts. `native::open` is the writer's `rw` mount,
  `native::open_shared` the readers'. In `list` the `Reading` guard drops after the share,
  so a waiting write finds the device unmounted.
- **`DeleteMany(as names)`** on `Helper2`: `check_delete_many` in core (two or more, each a
  snapshot name, none repeated; the client runs it before the call, the helper again),
  `refuse_if_running`, polkit `delete` once, one job; each name in order with the job's
  `snapshot` and `percent` (done of total); stops at the first failure with
  `Error::DeleteManyStopped { deleted, failed, left, reason }`, encoded in `Finished`'s
  message (`delete stopped: deleted=a,b failed=c left=d reason=<encoded reason>`), decoded
  by core. Journal: `delete-many ["a", "b", +1 more] for :1.42: started`, `deleted <name>`
  per name, `done` or `failed: delete stopped at <name>: <reason>`.
- **Core**: `JobKind::List` removed, `JobKind::DeleteMany` (`delete-many`) added,
  `JobKind::changes_the_list()`; `OP_DELETE_MANY`, `METHOD_DELETE_MANY`;
  `HelperClient::delete_many`.
- **Applet**: one `HelperClient` per process, made at start (`Message::Connected`), kept in
  the model, re-made on `Message::BusLost` (the job subscription is `Subscription::run_with`
  on a generation-hashed `JobSource`, so it follows the connection). `on_job` lists only
  when a create, delete or delete-many ended; the `helper_busy` re-list on any end is gone,
  the 5 s `BusyRetry` stays. A selection of several is one `DeleteMany` call; the progress
  line "Deleting 2 of 4: …" follows the helper's `JobChanged.snapshot`; the result text comes
  from the helper's account (deleted / failed / left), not from counting.
- **Packaging and docs**: `Exec=apsis` (no `%F`) in `resources/app.desktop`; version 0.4.2
  in `Cargo.toml`, `Cargo.lock` (only the three apsis crates), metainfo `<release>`, deb
  changelog, man page `.TH`, CHANGELOG (with the compare links for 0.4.1 and 0.4.2), README
  (status line, the delete paragraph), ARCHITECTURE (helper table: `List` as a read,
  `DeleteMany`, the job kinds; the call order: the write wait, the shared mount, release
  before announce; one client per process), one DECISIONS entry.
- **Tests added**: `State`: five readers at once, a write waiting for them with a sixth
  reader refused, a reader during a write refused, the write giving up on readers that
  never leave, the lock free before the end is announced, a job end then three reads and a
  write all going through; the shared mount with a fake runner (one `mount`, one `umount`
  for five overlapping readers; the writer's `rw` mount only after the `umount`; a reader
  for another device refused while one is mounted); `DeleteMany`'s name checks, steps,
  message encode/decode, interface introspection (8 methods, `as`); the applet: one
  connection first then the list, no reconnect loop without a helper, one list per end
  (a configure end doesn't list even when told busy; a delete-many end does), one
  `DeleteMany` call, the "2 of 2" line, the stopped-at text with the selection kept for what
  wasn't deleted, a disk removed mid-job.
- **Not done**: `just deb` and lintian (cargo-deb and the network aren't available in the
